# Step 02 — Comprehensive Descriptive and Temporal Data Audit

## 1. Purpose

The purpose of Step 02 is to understand the full structure of the Step 01 canonical dataset before any model-specific transformation, chronological splitting, hyperparameter tuning, or forecasting is performed.

This step answers the following practical questions:

- What variables are available and what numeric alternatives occur in each variable?
- How strongly is each variable represented?
- What are the location, spread, shape, zero-frequency, and missingness characteristics of each variable?
- How does `AffWB` differ across participants and ordered sequence positions?
- How much AffWB variation occurs between participants and within the same participant over time?
- How strong is sequential AffWB dependence across multiple lags?
- How do lagged social-media variables relate descriptively to later AffWB?
- How many usable targets remain under different candidate history lengths?

The results of this step will be used to design the separate data-preparation strategies for ARIMA/ARIMAX, RF/GBM/XGBoost, and RNN/LSTM in later steps.

## 2. Inputs

The default executable input is:

- `outputs/tables/01_prepared_long_data.csv`

This is the canonical occasion-level dataset generated by `01_prepare_data.py`. It contains the original participant sequences, numeric values, and separate status, observed, and availability indicators.

Step 02 does not read the raw CSV or SAV file directly. This preserves the dependency chain:

## 4. Analytical Decisions and Their Reasons

### 4.1 The occasion-level dataset remains unchanged

Step 02 does not average observations by day and does not write a transformed modeling dataset. All summaries are calculated from the source-row-level canonical data.

Day-based summaries are descriptive views only. They do not replace the original sequence.

### 4.2 No artificial expansion to 42 rows

Participants retain their actual number of source rows. No rows are added at the beginning or end of shorter sequences.

For visualization only, the AffWB status heatmap displays all planned occasion positions from 1 to 42. Empty heatmap cells identify positions for which no source row exists. This visual matrix is not saved as an analytical dataset and is not used as model input.

### 4.3 Sequential ordering is used without claiming exact time intervals

`Occasion` is treated as an ordered sequence index. Record 38 precedes record 39 for the same participant.

However, exact timestamps are unavailable and survey prompts were scheduled within time blocks. Therefore, Step 02 does not claim that adjacent occasions are separated by identical elapsed time.

`PlannedDayIndex` and `PlannedOccasionWithinDay` are used only to inspect patterns under the planned six-assessments-per-day schedule.

### 4.4 Missing values are not imputed

All descriptive statistics use observed numeric values only. Step 02 does not apply:

- mean or median imputation;
- forward filling;
- linear interpolation;
- replacement of missing social-media values with zero;
- model-based imputation.

The original missing-status indicators remain the source of truth.

### 4.5 Valid zero remains a real observed value

For social-media variables, zero means zero reported minutes during the previous hour. Zero frequencies and zero rates are reported explicitly because the predictors are expected to be highly zero-inflated.

### 4.6 Response missingness remains separate from structural unavailability

The analysis distinguishes:

- an available question with no numeric response;
- a platform-specific question that was structurally not asked;
- a valid observed zero;
- a valid observed nonzero value.

Platform questionnaire coverage is reported separately because low-coverage variables cannot automatically be treated as full-sample primary predictors.

### 4.7 Normality is assessed descriptively, not used as a binary decision rule

For every numeric measurement variable, Step 02 creates:

- descriptive statistics;
- skewness and excess kurtosis;
- Shapiro-Wilk and D'Agostino normality statistics where estimable;
- a histogram with a same-mean and same-SD normal reference curve;
- a normal Q-Q plot.

These tests are not interpreted as ordinary independent-sample tests because observations are repeated within participants. In addition, `AffWB` is bounded and ordinal, while social-media-minute variables are bounded and often zero-inflated. Visual and substantive interpretation is therefore more important than a normality p-value alone.

### 4.8 Participant-level heterogeneity is evaluated explicitly

The script calculates AffWB summaries for every participant and a descriptive one-way ICC(1) variance decomposition.

This is important because pooled accuracy can hide large differences between adolescents. Later modeling steps should evaluate both overall performance and performance variability across participants.

### 4.9 Multiple history lengths are evaluated without selecting one in advance

The candidate lookbacks are:

```text
1, 2, 3, 4, 5, 6, 9, 12, 18, 24, 30, 36 prior source rows
```

For every measurement variable and every lookback length, the script reports:

- candidate observed AffWB targets;
- participants represented;
- windows with 100% observed history;
- windows with at least 80% observed history;
- windows with at least 50% observed history;
- mean observed history fraction.

This table does not choose the final history length. It shows the data-loss consequences of each option.

For ARIMA/ARIMAX, a later step may use all available history before each forecast origin rather than a fixed lookback. The fixed-window audit is especially relevant to lag-feature models and RNN/LSTM sequence construction.

### 4.10 Temporal correlations are exploratory

Step 02 calculates:

- AffWB autocorrelation-like correlations for lags 1-12;
- pooled correlations;
- within-person-centered correlations;
- participant-specific lag-1 correlations where estimable;
- lagged social-media predictor correlations with later AffWB.

These results describe sequential association. They do not establish causality, select final predictors, or replace chronological model validation.

## 5. Quality Checks

The script stops if a critical requirement fails. It verifies:

- unique participant-occasion keys;
- ordering by participant and occasion;
- occasion range from 1 to 42;
- consistency of the planned day and within-day helper indices;
- agreement between observed flags and numeric values;
- agreement between structural statuses and availability flags;
- valid observed numeric ranges.

The results are written to:

- `outputs/tables/02_data_quality_checks.csv`

## 8. Boundary of Step 02

Step 02 does **not**:

- create model-ready lag matrices or neural-network tensors;
- select a final lookback length;
- select a final predictor subset;
- impute missing inputs;
- normalize or standardize predictors;
- create chronological train, validation, or test partitions;
- fit or tune any forecasting model;
- compare final model performance.

The next step should use the Step 02 evidence to define the shared prediction target, forecast origin, chronological validation design, and model-specific dataset construction rules.
